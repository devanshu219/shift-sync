Your shifts in Google Calendar, automatically

MLSE and Rogers Centre shifts show up in your Google Calendar with the event name and venue, and update by themselves. Free. About 15–20 minutes, once. Tick each step as you go; this page remembers your progress.

No GitHub account? Create a free one (2 min), then type the username here. It only fills in the buttons below; it isn't sent anywhere.

📱 Doing this on a phone?

A computer is easiest, but a phone works if you do these 3 things:

  1. Turn on desktop mode in your browser before you start. Google Calendar's settings (making the calendar, the Calendar ID, sharing) don't exist in the Calendar app or the phone version of the site.
    • iPhone Safari: tap aA in the address bar, then Request Desktop Website.
    • Android Chrome: tap ⋮, then tick Desktop site.
    Turn it on again on each new site (Google Calendar, Google Cloud, GitHub).
  2. Copying the key file (the .json from the robot step) is the trickiest part:
    • iPhone: open the Files app, then Downloads, and tap the .json file to preview it. Press and hold on the text, tap Select All, then Copy.
    • Android: open Files, then Downloads, and open the .json file with a text viewer. Select all, then copy.
    • Paste it as the GCAL_SERVICE_KEY secret. Check it starts with { and ends with }.
  3. Keep a Notes app open for the 2 things you copy (Calendar ID, robot email). Switch between apps with the app switcher.

If anything looks different, finish that step later on a computer. Your ticks on this page are saved.

Check your work logins · 2 min

Type them by hand (no autofill). The sync uses exactly what works here.

Open MLSE WorkForce Log in with your User ID and password.

Open Rogers ESS Venue LEGENDSTBJ, then your employee number and PIN, then View My Schedule.

Supervisor or a different ESS screen? If your shifts aren't under "View My Schedule", the Rogers part may not read them. MLSE still works.

Make a "Work Shifts" calendar · 1 min

Create a new Google Calendar
  1. Name it Work Shifts and click Create calendar.
  2. Click it in the left list, then scroll to Integrate calendar.
  3. Copy the Calendar ID (it ends with @group.calendar.google.com) into Notes as "Calendar ID".

Keep this tab open. You'll share the calendar two steps from now.

📱 On a phone, turn on desktop mode first (see "Doing this on a phone?" above). The Calendar app can't do this step.

Create the Google "robot" that writes to your calendar · 5 min

Use the same Google account. No credit card needed; skip any free-trial offer. Do these four buttons in order:

  1. ① Create project Name it shift-sync, click Create, then wait about 10 seconds.
  2. ② Turn on Calendar API Check the top bar shows shift-sync, then click Enable.
  3. ③ Create the robot Name it calendar-sync, then Create and continue, Continue, Done.
  4. ④ Get its key Click the robot's email, then Keys, Add key, Create new key, JSON, Create. A .json file downloads. Also copy the robot's email (ends with .iam.gserviceaccount.com) into Notes.

"Key creation is disabled"? You're on a work or school Google account. Use a personal @gmail.com account instead.

Let the robot write to "Work Shifts" · 1 min

Open Calendar settings
  1. Click Work Shifts on the left, then Share with specific people or groups, then Add people and groups.
  2. Paste the robot email, set Make changes to events, then Send. A "can't send email" warning is fine.

Get your own copy of the sync · 30 sec

Create my copy

Make sure Private is selected (it keeps your shifts private), then click Create repository. All the code is already in it.

Add your private details · 3 min

Open "New secret"

For each one, paste the Name, put the value in Secret, click Add secret, then reopen the button for the next one. Type passwords and PINs by hand.

GCAL_SERVICE_KEYOpen the downloaded .json in Notepad or TextEdit, then select all and copy. On a phone: see "Doing this on a phone?" above.
CALENDAR_IDCalendar ID from Notes
MLSE_USERMLSE User ID
MLSE_PASSMLSE password
ESS_USERESS employee number

Afterwards you can delete the .json file from Downloads and clear your Notes.

Safety cap, then run it · 3 min

  1. $0 safety cap Choose Product-level budget, then Actions, then Next. Set the amount to 0, tick Stop usage when budget limit is reached, then Create budget. GitHub can then never charge you.
  2. Run it now If asked, enable workflows. Then Run workflow, then Run workflow.
  3. After about 2 minutes, open the run. Its Summary shows a ✅ / ❌ checklist of anything that still needs fixing.
  4. MLSE: run it once more a minute later. The second run adds the event names.

Rogers off-season: it only checks ESS at 10 AM and 4 PM. To test now, add a secret ROGERS_FORCE_CHECK with value 1, run, then delete that secret.

After this it runs by itself: hourly from 10 AM to 10 PM, plus 7 AM, 9 AM, 11 PM and 3 AM, using well under GitHub's free 2,000 minutes a month. If you change your MLSE password or ESS PIN, update that secret. Stuck? Open the run's Summary, or send whoever shared this page a screenshot of the ❌.
